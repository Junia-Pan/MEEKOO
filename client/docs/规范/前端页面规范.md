# 前端页面规范（client-pages）

> 规范入口请见：`规范索引.md`

## 菜单入口页面 - 列表复选框列（统一规范）

### 适用范围

- 左侧菜单入口进入的“列表页”（例如：货件管理各子页、一件代发、工单列表等）。

### 统一 UI/交互要求（必须）

- **最左侧必须提供复选框列**，用于批量操作预留。
- **表头提供全选（本页）**：勾选后选中当前分页内所有行；取消勾选则取消当前分页内所有行。
- **行点击不应被复选框误触影响**：点击复选框仅改变选中状态，不触发行点击详情/选中行事件。

### 推荐实现（静态页面最小实现）

- 在 `state` 中增加 `selectedIds: new Set()`（主键建议用 `id/systemNo` 这类稳定字段）。
- 渲染时同步表头全选的 `checked/indeterminate` 状态。
- 翻页/筛选后，仍保留 `selectedIds`（如需“切换筛选清空”，应显式清空）。

## 查询条件 - 日期/时间范围控件（统一规范）

### 适用范围

- 所有“按日期/时间范围查询”的筛选条件（例如：创建时间、签收日期、提货日期、到仓日期等）。
- 页面位于 `client-pages/*.html` 的纯静态实现。

### 统一 UI 要求（必须）

- **一个输入框外观**：开始/结束日期在同一个边框内。
- **占位文案**：未选择时显示 `开始日期`、`结束日期`。
- **分隔符**：中间显示 `→`。
- **单日历图标**：右侧仅保留一个日历图标按钮（点击优先聚焦到未填写的日期）。
- **隐藏浏览器原生 `yyyy/mm/dd` 提示**：避免与占位文案重叠。

> 本项目已在公共样式 `client-pages/_styles.css` 内提供 `.date-range` 相关样式；并在 `client-pages/_ui-kit.js` 内提供 `wireDateRanges()` 负责占位/样式状态同步。

### 标准 HTML 结构（复制使用）

```html
<div>
  <label class="label">创建时间</label>
  <div class="date-range">
    <div class="dr-field">
      <span class="dr-ph">开始日期</span>
      <input class="input" id="q_createdFrom" type="date" aria-label="创建时间开始" />
    </div>
    <span class="dr-arrow">→</span>
    <div class="dr-field">
      <span class="dr-ph">结束日期</span>
      <input class="input" id="q_createdTo" type="date" aria-label="创建时间结束" />
    </div>
    <button class="dr-ico" type="button" aria-label="选择创建时间范围" title="选择创建时间范围">
      <svg xmlns="http://www.w3.org/2000/svg" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
        <rect x="3" y="4" width="18" height="18" rx="2" ry="2"></rect>
        <line x1="16" y1="2" x2="16" y2="6"></line>
        <line x1="8" y1="2" x2="8" y2="6"></line>
        <line x1="3" y1="10" x2="21" y2="10"></line>
      </svg>
    </button>
  </div>
</div>
```

### JS 初始化要求（必须）

- 页面脚本需从 `window.MEEKOO_UI` 解构 `wireDateRanges`，并在页面初始化时调用一次：

```js
const { wireDateRanges } = window.MEEKOO_UI;
try { wireDateRanges && wireDateRanges(document); } catch {}
```

### 查询逻辑要求（建议）

- 日期范围输入的 `id` 保持为现有查询逻辑使用的字段（例如 `q_createdFrom` / `q_createdTo`），避免影响 `getQuery()` 与筛选函数。
- 过滤逻辑以“天”为粒度（`00:00:00`～`23:59:59`）进行范围判断，保证符合用户对日期筛选的预期。

## 日期 / 时间显示与输入格式（统一规范）

### 适用范围

- admin / client 全部页面：列表、详情、弹窗表单、筛选条件中的日期与时间展示与输入。

### 统一要求（必须）

- **占位与格式文案一律使用英文数字格式**，禁止中英混写。
  - ✅ 正确：`yyyy-mm-dd`、`yyyy-mm-dd HH:mm`、`yyyy/mm/dd`
  - ❌ 错误：`yyyy/mm/日`、`年/月/日`、`yyyy年mm月dd日`（作占位提示时）
- **推荐统一占位**：
  - 仅日期：`yyyy-mm-dd`
  - 日期+时间：`yyyy-mm-dd HH:mm`
- 列表/详情已选值的展示也优先用英文格式（如 `2026-04-23 08:30`），不要用「2026年4月23日」这类混排占位。
- 若使用浏览器原生 `date` / `datetime-local`：注意中文系统下可能出现 `yyyy/mm/日` 等本地化空态文案；**表单需要明确英文占位时，优先用可控的文本输入 + `placeholder="yyyy-mm-dd HH:mm"`**（或等价英文占位），避免依赖系统语言。

### 示例

```html
<!-- 推荐：英文占位，格式可控 -->
<input class="form-input" type="text" placeholder="yyyy-mm-dd HH:mm" lang="en" autocomplete="off" />
```

## Toast 提示位置（统一规范）

### 适用范围

- admin / client 全部页面：成功、警告、失败等短时提示（Toast），含弹窗打开时弹出的校验提示。

### 统一要求（必须）

- **固定显示在屏幕正中**（水平、垂直居中），不要贴在右上角、右下角等边角。
- 弹窗打开时，Toast 仍居中并叠在弹窗之上，避免被弹窗挡住或贴边被忽略。
- 不拦截点击：提示本身不挡住弹窗按钮的点击（`pointer-events: none`）。
- **样式**：浅色底 + 深色文字，用背景色区分成功/警告/失败，不要整块纯色填充，也不要左侧加粗色条。
- 实现入口：admin 使用 `showToast()`（`admin/js/common.js` + `.ui-toast`）；client 使用 `_ui-kit.js` 的 `toast()` + `.toast-host`。

### 示例

```css
/* admin：.ui-toast 相对视口居中 */
.ui-toast { position: fixed; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* client：.toast-host 铺满视口并 flex 居中 */
.toast-host { position: fixed; inset: 0; display: flex; align-items: center; justify-content: center; }
```

## 文件上传（拖拽 + 点击）（统一规范）

### 适用范围

- admin / client 全部页面：弹窗表单、详情页、导入弹窗等**任何文件上传**入口（附件、凭证、POD、Excel 导入等）。

### 统一要求（必须）

- **禁止**仅用浏览器原生 `input[type=file]` 作为唯一主交互（避免只有「选择文件 / 未选择任何文件」）。
- **必须**提供虚线边框上传区，同时支持：
  1. **点击**区域打开系统文件选择；
  2. **拖拽**文件到区域释放以上传。
- 拖入过程中须有明显反馈（如高亮边框 / 浅蓝背景，类名建议 `is-drag`）。
- 主文案统一用：**「点击或拖拽…到此处上传」**（可按业务写清文件类型，如「点击或拖拽发车凭证到此处上传」）。
- 副文案（hint）写清：允许格式、是否多选、大小限制等。
- `accept`、`multiple` 与业务校验一致；拖入的文件也要走同一套校验。

### 推荐 HTML 结构

```html
<div class="file-drop" tabindex="0" role="button" aria-label="上传附件">
  <input type="file" hidden accept=".pdf,.jpg,.jpeg,.png,application/pdf,image/*" />
  <div class="file-drop-title">点击或拖拽文件到此处上传</div>
  <div class="file-drop-hint">支持 PDF / JPG / PNG</div>
</div>
```

### 交互要点

- 点击 drop 区域（非内部已有按钮）→ `input.click()`。
- `dragenter` / `dragover`：`preventDefault` + 加 `is-drag`；`dragleave`（离开区域）去样式；`drop`：`preventDefault`、取 `dataTransfer.files`、去样式、交给既有上传逻辑。
- 可选：键盘 Enter / Space 打开文件选择。
- 已有文件列表（预览 / 删除 / 下载）与上传区分离展示，不要把新旧文件混在同一无提示行里。
