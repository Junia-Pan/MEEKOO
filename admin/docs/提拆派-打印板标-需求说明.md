# 提拆派 · 打印板标 — 需求说明

| 项目 | 说明 |
|------|------|
| 模块 | 提拆派计划 · 打印板标；板标查询 |
| 范围 | 仅业务类型为「拆柜」的计划 |

---

## 1. 入口逻辑

1. 列表「更多 → 打印板标」。
2. 必须且仅勾选 **1 条**计划；0 条 / 多条拦截。
3. 业务类型 ≠ 拆柜 → 拦截：「仅业务类型为「拆柜」的计划可打印板标」。
4. 计划状态（待提柜 / 已到仓 / 已拆柜等）**不限制**打开。
5. 打开后顶栏带出：系统单号、柜号、计划状态、拆柜报告状态（未开始 / 已完成）。

---

## 2. 板标状态逻辑

生命周期（单向）：

```
草稿 → 待上架 → 已上架 → 待出库
```

| 状态 | 业务含义 | 可否被「板标修正」自动删除 |
|------|----------|----------------------------|
| 草稿 | 预生成，未正式入库 | 可以（优先删） |
| 待上架 | 已生成，未上架 | 可以 |
| 已上架 | 已在库 | **不可以** |
| 待出库 | 在库待出 | **不可以** |

- 板标查询：统计「在库总板数」及四态数量；可按四态筛选。

---

## 3. 合组展示逻辑

主表按合组规则渲染，不是一票一行无脑列出。

### 3.1 自动合组 → 主表一行汇总

| 条件 | 合组键 | 主表 |
|------|--------|------|
| 可参与 FBA 自动合组 | 相同 **FBA Code** | 一行；件数/板数合计；Ref / FBA ID 可并列 |
| Move Type ∈ DHL / Fedex / UPS / USPS | 相同 **Move Type** | 一行（如全部 Fedex 一行） |

各票明细：点「查看货件明细」进二级弹窗。

### 3.2 主动合并打板 → 主表按票列行 + 合并单元格

用户「合并打板」形成的合组：

- 组内 **每一票各占一行**（**FBA Code**、Ref、FBA ID、预报件数、预估板数、拆柜要求按票显示，互不合并）。
- 以下列 **rowspan**：勾选、Move type、实际件数、实际板数、收费板数、操作。
- 不另打「合板」角标；用 rowspan 识别主动合板。
- 「打印板标 / 查看货件明细」作用于整组。

主表与货件明细均展示 **收费板数**（与拆柜报告同口径；未填时回落实际板数）。

---

## 4. 合并打板 / 取消合并逻辑

### 4.1 何时允许

| 拆柜报告状态 | 合并 / 取消合并 |
|--------------|-----------------|
| **未开始** | 允许 |
| 已完成（或其它非未开始） | **禁止** |

与计划状态无关。按钮、勾选**始终展示**，不隐藏；禁止时点按钮再提示：

- 「仅拆柜报告「未开始」时可合并打板」
- 「仅拆柜报告「未开始」时可取消合并」

### 4.2 合并校验（按顺序）

1. 至少勾选 **2** 条（按货件计）。
2. 类型仅限：**私卡派 / 留仓 / 自提 / 扣货**；其它类型勾选禁用或拦截。
3. 必须 **同一 Move Type**；不可跨类型合（留仓只能合留仓，扣货只能合扣货，以此类推）。
4. 所选合组 **已有板标** → 拦截：须先删板标再合并。
5. 二次确认通过后写回合组关系（与拆柜报告共用数据）。

### 4.3 取消合并

1. 须勾选要拆出的货件。
2. 报告非「未开始」→ 点击提示，不执行。
3. 组上已有板标 → 须先删板标。
4. 二次确认后从合组拆出。

---

## 5. 板标修正逻辑（建立 / 保存拆柜报告）

**核心：已有板标张数 > 实际板数时，系统按实际板数自动删多余，不靠人工一张张删。**

### 5.1 触发

- 建立拆柜报告并保存
- 修改拆柜报告（实际板数调低）并保存

### 5.2 对齐（按合组分别算）

对每个合组（自动合组或主动合板组）：

| 比较 | 处理 |
|------|------|
| 已有张数 **>** 实际板数 | 自动删除 `(已有 − 实际)` 张，使张数 = 实际板数 |
| 已有 = 实际 | 不处理 |
| 已有 **<** 实际 | **不**自动补板；走「添加 / 录入板标」 |

示例：预生成 10 张，实际改为 8 → 自动删 2，剩 8。

### 5.3 删谁、删不动怎么办

1. 只删 **草稿、待上架**；优先草稿，再待上架；同状态优先删序号靠后的。
2. **已上架、待出库** 一律不删。
3. 需要删的张数 > 可删张数 → **拦截保存**，提示先处理已上架/待出库板，或改回实际板数。
4. 草稿 / 待上架即使已打印，多余仍可删（以实际板数为准）。

### 5.4 和改合组的关系

- 「有板标不可直接改合组」门禁仍在；本规则**不替代**先删板再合并。
- 合组变更后再保存：按 **变更后合组** 的实际板数再跑一遍自动删多余。

---

## 6. 打印逻辑

| 操作 | 逻辑 |
|------|------|
| 行内「打印板标」 | 只打当前行 / 合组的待打印板标 |
| 「打印全部板标」 | 打本柜全部待打印板标 |
| 前置 | 须已建立拆柜报告；PDA 来源板标只读提示 |

---

## 7. 货件明细

「查看货件明细」→ 二级弹窗展开当前合组各票（含预报件数、预估板数、预报重量 LB/KG、预报体积、实际件数/板数、收费板数、拆柜要求等）；KG 由 LB 换算；可导出。

---

## 8. 板标查询

- 状态：草稿 / 待上架 / 已上架 / 待出库
- 筛选：全部 + 上述四态
- 统计：在库总板数及各状态数量
