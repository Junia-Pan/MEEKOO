# 排货总览 · 合计维度 — 产品需求文档 (PRD)

## 1. 文档说明

明确 FBA 发货计划「排货总览」中做计划与看合计的稳定维度：以当前目的仓代码与柜号为主，用行来源区分原单、转仓、拦截回流；转仓与改派送方式可多次发生，合计层按当前身份合并、按事件搬量，不按变更次数拆行，避免维度过散导致排漏。

### 1.2 名词解释

| 专有名词 | 解释/定义 |
|----------|-----------|
| 排货总览 | 员工端 FBA 发货计划中，按仓与柜查看待排/已排货量并创建发货计划的总览页 |
| FBA Code | 当前目的 FBA 仓代码（如 ONT8），做计划与主表合计的目的仓标识 |
| 下单 FC | 下单时的履约仓/FC 信息；展示与筛选用，不作为合计拆行依据 |
| 柜号 | 集装箱号；与 FBA Code 共同构成计划与合计单位 |
| 行来源 | 货量当前进入该目的仓可排池的身份分类：原单 FBA、转仓、拦截回流 |
| 原单 FBA | 下单即为 FBA 货，且当前仍在该 FBA Code，未因转仓离开，也未走过拦截/非 FBA 后再回流 |
| 转仓 | 将货件从当前目的仓改到新的 FBA Code；转仓后清空与原计划的绑定 |
| 拦截回流 | 货件曾改为拦截或非 FBA，处理后再改回可排的 FBA；须单独看待并重新排计划 |
| 拆柜前 | 尚未完成拆柜：含在途、在仓待拆 |
| 拆柜后 | 已完成拆柜：含在仓未排、在仓已排 |
| 合计键 | 排货总览主表一行对应的稳定身份：行来源 + 当前 FBA Code + 柜号 |
| 同键合并 | 多次事件后，量并入同一合计键，不按第 N 次事件新开行 |

## 2. 产品概述

### 2.1 产品背景

排货以「FBA Code + 柜号」为单位做计划。实际业务中常见：

1. 下单即为 FBA 货，下单后即可排计划。  
2. FBA 货发生转仓，目标仓与原仓不同；若只按当前 FBA Code + 柜号静默并入，会混进目标仓已有「已排」计划，不够清晰。  
3. 下单非 FBA 后改成 FBA，或 FBA 在拆柜过程中将派送方式改为拦截、处理后再改回 FBA；此类货若混进原已排计划，容易排漏或误判。  
4. 下单 FC 在拆柜前可随意改，拆柜后不可随意改；换目的仓须走转仓。  
5. **转仓与改派送方式（含拦截）均可发生多次**。若每次变更都新开合计行，行数随变更日志膨胀，合计更散，反而更易排漏。

因此需要约定：哪些情况必须单独成行、哪些变更只记日志并合并到当前行。

### 2.2 目标用户

| 用户角色 | 特征与诉求 |
|----------|------------|
| 排货 / 计划员 | 按仓+柜凑车；要一眼区分原单、转仓、回流货；避免把例外货当成已排原单 |
| 仓配运营 | 看各 FBA 仓可排/已排/拆柜前总量；例外货量可下钻，但不希望侧栏维度过碎 |
| 客服 / 单证 | 查询转仓前仓码、变更次数；完整路径以操作日志为准 |

### 2.3 产品目标

| 类型 | 目标说明 |
|------|----------|
| 定性 | 合计维度稳定、上限可控；转仓与拦截回流与原单隔离；多次变更不导致合计行无限增多 |
| 定性 | 下单后即可按 FBA Code + 柜号做计划；变更全量可追溯，但不抬升为合计交叉维 |
| 定量 | 同一 FBA Code + 柜号下，主表合计行最多三种行来源（原单 FBA、转仓、拦截回流） |

**本期不包含：**

- 按历史下单 FC、历史派送方式、第 N 次转仓做多维交叉合计矩阵  
- 在中间目的仓保留已转走量的「幽灵合计行」  
- 排货总览以外模块的完整派送方式变更产品细则（本模块只约定回流后如何回到合计与计划池）

### 2.4 关联模块

| 关联模块 | 与本模块关系 |
|----------|--------------|
| FBA 发货计划（计划单） | 做计划单位与合计键一致；转仓须清空原计划绑定；回流货不得静默挂回旧计划 |
| 提拆派 / 货件派送方式变更 | 改为拦截或非 FBA 时货量离开 FBA 可排池；改回 FBA 后以拦截回流进入排货总览 |
| 装车 / 派送 / 退仓 | 退仓回排货总览等既有规则不变；回池后仍须遵守本合计维度与行来源规则 |

## 3. 业务流程与架构

### 3.1 核心业务规则总览

**稳定合计键：**

> 行来源（原单 FBA / 转仓 / 拦截回流） + 当前 FBA Code + 柜号

**核心原则：**

1. 「单独成行」指当前身份分类，不是事件流水账。  
2. 事件改变的是「量落在哪一把合计键上」，不是「再增加一把新钥匙」。  
3. 历史次数与完整路径只进入操作日志及行上弱提示（如转仓次数），不进入合计键。  
4. 下单 FC、派送方式的日常改码，只区分拆柜前/后的权限与流程，不作为合计交叉维。

**主路径示意（文字）：**

- 下单即 FBA → 进入「原单 FBA + 该 FBA Code + 柜号」，下单后即可排计划。  
- 转仓（可多次）→ 源合计键扣减转走量并解绑相关计划 → 量并入「转仓 + 目标 FBA Code + 柜号」（有则加量，无则建一行）；中间仓不保留已转走量。  
- 改为拦截或非 FBA（可多次）→ 从当前 FBA 合计键扣量，暂离排货总览 FBA 可排池。  
- 再改回 FBA（可多次）→ 量并入「拦截回流 + 当前 FBA Code + 柜号」，状态为在仓未排（或拆柜前对应状态），禁止静默挂回旧计划。

### 3.2 与计划、侧栏统计的关系

| 视图 | 聚合方式 | 用途 |
|------|----------|------|
| 主表 | 一行 = 一个合计键的当前快照 | 做计划、勾选、转仓、区分行来源 |
| 左侧 FBA 仓统计 | 按 FBA Code 汇总板数或方数 | 看仓总量；例外货用角标提示，不按历史交叉拆列 |
| 操作日志 | 按货件/系统单记录全量变更 | 追溯第 N 次转仓、派送方式变更路径 |

## 4. 需求详细说明

### 4.1 产品方案概述

1. 主表按「行来源 + 当前 FBA Code + 柜号」展示与合计；同一键只保留一行。  
2. 仅三类行来源；与同柜同目的仓的其他来源并列，互不合并。  
3. 多次转仓、多次改派送方式：搬量 + 同键合并；展示最近一次转仓前仓码与次数。  
4. 拆柜前/后约束下单 FC 与换仓方式；侧栏列收成可排、已排、拆柜前，避免过碎。

### 4.2 核心功能一览

#### 4.2.1 四大核心能力

| 序号 | 核心能力 | 解决什么问题 | 关键功能点（P0） |
|:----:|----------|--------------|------------------|
| ① | **稳定合计键** | 防止按变更日志无限拆行 | 行来源 + FBA Code + 柜号；同键一行 |
| ② | **例外货隔离** | 转仓/回流不混入原单已排 | 三类行来源并列；回流默认未排 |
| ③ | **多次事件搬量** | 转仓与拦截可反复发生 | 扣源并目标；不按次数开新行 |
| ④ | **拆柜前后改码边界** | FC 乱改导致计划混乱 | 拆柜前可改 FC；拆柜后换仓走转仓 |

#### 4.2.2 核心功能点索引

| 核心功能点 | 说明摘要 | 详述章节 |
|------------|----------|----------|
| 合计键与行来源 | 三种身份定义、并列不合并、上限 | **4.3.1** |
| 多次转仓 | 搬量规则、展示最近转仓前 FC、次数 | **4.3.2** |
| 多次改派送方式与拦截回流 | 离开可排池、回流合并、禁止挂回旧计划 | **4.3.3** |
| 下单 FC 与拆柜前后 | 改码权限；不拆合计行 | **4.3.4** |
| 主表与侧栏统计 | 列结构、角标、筛选 | **4.3.5** |
| 做计划联动 | 下单后可排；转仓清空绑定 | **4.3.6** |

#### 4.2.3 其他功能

| 功能 | 说明 |
|------|------|
| 货件明细下钻 | 合计行可查看下属货件；不改变合计键 |
| 操作日志 | 全量记录转仓、派送方式、下单 FC 等变更 |

### 4.3 具体功能详述

#### 4.3.1 【合计维度】合计键与行来源

- **使用场景：** 排货员打开排货总览，按行勾选做计划或查看某仓某柜货量。  
- **前置条件：** 货件属于 FBA 可排范围（当前派送方式为可排 FBA，且未因拦截等离开本池）。  
- **操作流程：**  
  1. **进入排货总览：** 系统按合计键聚合展示当前可排/在池货量。  
  2. **识别行来源：** 每行展示原单 / 转仓 / 拦截回流标识。  
  3. **选择后续操作：** 查询、勾选做计划、转仓、查看明细或日志（见各节）。  

- **业务规则（核心）：**

| 行来源 | 当前含义 | 与「原单」关系 |
|--------|----------|----------------|
| 原单 FBA | 下单即 FBA，且当前仍在该 FBA Code，未因转仓离开，也未走拦截/非 FBA 回流 | 主路径 |
| 转仓 | 当前落在该 FBA Code，因转仓进入（可经过多次转仓） | 与同柜同 FBA Code 的原单行**并列不合并** |
| 拦截回流 | 当前又是可排 FBA，但中间离开过（拦截或非 FBA→FBA 等） | 与原单、转仓**并列不合并**；须重新排计划 |

| 规则 | 说明 |
|------|------|
| 合计键唯一 | 同一「行来源 + 当前 FBA Code + 柜号」仅一行 |
| 行数上限 | 同一 FBA Code + 柜号最多三行（三种来源各一行） |
| 判定依据 | 货件**当前**如何处于该目的仓可排池，而非累计事件次数 |
| 禁止 | 按第 N 次转仓、第 N 次改派送方式、历史下单 FC、历史派送方式拆合计行 |

- **异常处理：** 某来源量扣减至零时，该合计行消失或不再展示，不得保留零量占位干扰排货。

#### 4.3.2 【合计维度】多次转仓

- **使用场景：** 货件需更换目的 FBA 仓，且可能连续转仓多次。  
- **前置条件：** 已选中待转仓货件；填写新 FBA Code 与转仓原因；确认转仓将清空绑定计划。  
- **操作流程：**  
  1. **勾选货件并发起转仓。**  
  2. **填写新 FBA Code、转仓原因并确认。**  
  3. **系统处理：** 源合计键扣减转走量；解绑相关计划；将量并入「转仓 + 新 FBA Code + 柜号」。  
  4. **再次转仓：** 重复以上步骤；规则与第一次相同。  

- **业务规则（核心）：**

| 规则 | 说明 |
|------|------|
| 第 N 次与第 1 次相同 | 均为：源扣量 + 解绑计划 + 目标同键合并 |
| 同目标合并 | 同柜、同目标 FBA Code 的转入量，全部进入同一「转仓」行，不按转仓前仓码再拆 |
| 无幽灵行 | 已转走的量不得留在中间 FBA Code 的合计中 |
| 与原单隔离 | 目标仓若已有「原单 FBA + 同 FBA Code + 同柜」，转仓行与之并列 |
| 展示 | 「转仓前 FC」展示**最近一次**转仓前所在仓码；旁注转仓次数；完整链路仅日志 |

- **交叉事件：** 若货件当前为「拦截回流」再转仓，则从拦截回流行扣量，进入目标「转仓」行（换仓优先用转仓身份与目标仓原单隔离）。  

- **异常处理：** 未填新 FBA Code 或原因时不可确认；转仓失败不得部分扣量导致双边不一致。

#### 4.3.3 【合计维度】多次改派送方式与拦截回流

- **使用场景：** 派送方式改为拦截或非 FBA，处理后再改回 FBA；过程可反复。  
- **前置条件：** 在提拆派或货件侧完成派送方式变更（本模块消费结果）。  
- **操作流程：**  

**路径一：离开 FBA 可排池**

1. **派送方式改为拦截或非 FBA。**  
2. **系统从当前合计键扣减对应量。**  
3. **该量不再计入排货总览 FBA 合计与可排计划池。**  

**路径二：回流为可排 FBA**

1. **派送方式改回可排 FBA。**  
2. **量并入「拦截回流 + 当前 FBA Code + 柜号」（有则加量）。**  
3. **计划状态回到未排（拆柜后）或保持拆柜前对应状态；不得静默挂回变更前的旧计划。**  
4. **再次拦截再回流：** 仍并入同一「拦截回流」合计键，仅追加日志与次数提示。  

- **业务规则（核心）：**

| 规则 | 说明 |
|------|------|
| 离开不计 FBA 合计 | 拦截/非 FBA 期间不占 FBA 排货合计行，避免与已排原单混淆 |
| 回流同键合并 | 无论回流多少次，同一 FBA Code + 柜号只有一条拦截回流行 |
| 必须重排 | 回流货视为需重新纳入计划，不得当作原「已排」未发生变化 |
| 中间变更不拆行 | 派送方式每次变更只记日志，不新开合计行 |

- **异常处理：** 回流时若目的仓代码缺失或非法，不得并入错误合计键；须待业务补全后再入池。

#### 4.3.4 【合计维度】下单 FC 与拆柜前后边界

- **使用场景：** 修正下单 FC，或拆柜后需要更换目的仓。  
- **前置条件：** 货件处于拆柜前或拆柜后相应状态。  
- **操作流程：**  

**路径一：拆柜前修改下单 FC**

1. **修改下单 FC。**  
2. **原地更新当前合计行展示值。**  
3. **不新开合计行，不按历史 FC 留版本行。**  

**路径二：拆柜后更换目的仓**

1. **不可随意改下单 FC 达到换仓效果。**  
2. **须走转仓流程（见 4.3.2）。**  

- **业务规则（核心）：**

| 阶段 | 下单 FC | 派送方式 |
|------|---------|----------|
| 拆柜前（在途、在仓待拆） | 可随意改；原地更新；不拆行 | 可改；不按历史值拆行 |
| 拆柜后（在仓未排、在仓已排） | 不可随意改；换仓走转仓 | 可多次改拦截/回流；按 4.3.3 |

「只区分拆柜前和拆柜后」指**改码权限与流程边界**，不是再按拆柜前/后各拆一套下单 FC × 派送方式合计矩阵。

- **异常处理：** 拆柜后尝试直接改 FC 换仓时，应提示走转仓，并阻止产生错误合计拆分。

#### 4.3.5 【合计维度】主表与侧栏 FBA 仓统计

- **使用场景：** 主表做计划；侧栏看各仓量。  
- **前置条件：** 无。  
- **操作流程：**  
  1. **查看侧栏某 FBA Code 总量。**  
  2. **按需点击仓码或例外角标，主表过滤到对应仓/行来源。**  
  3. **在主表按合计行勾选做计划或转仓。**  

- **业务规则（核心）：**

**主表**

| 项 | 要求 |
|----|------|
| 一行含义 | 一个合计键的当前快照 |
| 必显 | 行来源标识；FBA Code；柜号 |
| 转仓行 | 最近转仓前 FC；转仓次数 |
| 拦截回流行 | 可弱提示离开/回流次数 |
| 下钻 | 货件明细；变更全量在日志 |

**侧栏 FBA 仓统计**

| 项 | 要求 |
|----|------|
| 行 | 按 FBA Code（可继续分热门仓 / 偏仓） |
| 列 | **可排**（拆柜后·在仓未排）、**已排**（拆柜后·在仓已排）、**拆柜前**（在途 + 在仓待拆）、**合计** |
| 计量 | 支持按板数 / 方数切换查看 |
| 例外 | 转仓、拦截回流量计入对应列；角标提示「含转仓 / 含拦截回流」，点击后主表按行来源筛选 |
| 禁止 | 按历史下单 FC、历史派送方式、转仓次数开矩阵列 |

- **异常处理：** 筛选后无行时明确空态；角标数量与主表过滤结果一致。

#### 4.3.6 【合计维度】做计划联动

- **使用场景：** 下单后即可排计划；对转仓行、拦截回流行重新排计划。  
- **前置条件：** 合计行有可排量。  
- **操作流程：**  
  1. **勾选合计行（或下钻后的货件）。**  
  2. **创建或加入发货计划。**  
  3. **若之后转仓：** 清空绑定计划，量进入目标转仓行待重排。  
  4. **若之后拦截再回流：** 以拦截回流行未排状态待重排。  

- **业务规则（核心）：**

| 规则 | 说明 |
|------|------|
| 下单即可排 | 原单 FBA 不依赖拆柜完成即可进入计划编排（量计入拆柜前或拆柜后对应列） |
| 转仓解绑 | 转仓确认后清空原计划绑定（与现有转仓提示一致） |
| 回流不解挂旧计划 | 拦截回流不得自动恢复为变更前「已排」 |
| 同柜多来源 | 原单、转仓、拦截回流须分别勾选、分别纳入计划，禁止一键误并 |

- **异常处理：** 已排量与计划单不一致时，以计划侧校验为准并提示刷新。

## 5. 界面与交互需求

界面以现有排货总览原型为准；本节仅列与合计维度相关的业务要点。

### 5.1 主表

- 须能区分行来源（原单 / 转仓 / 拦截回流），避免仅靠 FBA Code + 柜号误并。  
- 转仓行须能看到最近转仓前仓码及转仓次数。  
- 支持按 FBA Code、柜号、行来源筛选。  
- 合计行可下钻货件明细；完整变更看操作日志。  

### 5.2 侧栏 FBA 仓统计

- 列展示可排、已排、拆柜前、合计；避免维持过细的四状态与例外交叉矩阵。  
- 含转仓或拦截回流时须有角标或等价提示，并支持点选过滤主表。  

### 5.3 转仓

- 须先勾选；新 FBA Code、转仓原因必填。  
- 确认前须明确提示：转仓后将清空绑定的计划。  

### 5.4 交互反馈

| 场景 | 交互要求 |
|------|----------|
| 拆柜后试图直接改 FC 换仓 | 拦截并提示走转仓 |
| 转仓确认 | 二次确认；强调清空计划 |
| 回流进入未排 | 提示需重新排计划，勿假定仍在原计划中 |

## 6. 非功能性需求

### 6.1 性能需求

- 合计按键聚合后主表行数应显著少于「每次变更一行」的膨胀模型；侧栏按仓汇总需在常用数据规模下可即时筛选联动。  

### 6.2 安全需求

- 转仓、改派送方式导致的入池/出池须留操作日志，可审计。  

### 6.3 兼容性需求

- 与既有退仓回「在仓未排」、装车/派送状态机兼容；回池后仍遵守本行来源规则。

## 8. 上线与运维计划

- **数据初始化：** 存量货按「当前是否在 FBA 可排池、是否曾转仓进入当前仓、是否曾拦截/非 FBA 回流」归入三种行来源；无法判定的默认原单 FBA，并允许运营校正。  
- **培训与支持：** 向排货员说明：单独成行是身份隔离，不是每次转仓/拦截都多一行；次数看日志与角标。  
- **回滚策略：** 若行来源归类异常，可按日志回放校正合计键，避免重复计量。

### 附录 A：行来源交叉事件速查

| 当前状态 | 再发生 | 合计结果 |
|----------|--------|----------|
| 原单 FBA @ 仓 A | 转仓 → 仓 B | 仓 A 原单扣量；并入「转仓 + 仓 B + 柜」 |
| 转仓 @ 仓 B | 再转仓 → 仓 C | 仓 B 转仓扣量；并入「转仓 + 仓 C + 柜」 |
| 任意 FBA 行 | 改拦截或非 FBA | 当前键扣量；离开 FBA 可排池 |
| 已离开 | 改回 FBA @ 仓 X | 并入「拦截回流 + 仓 X + 柜」（未排） |
| 拦截回流 @ 仓 A | 再转仓 → 仓 B | 仓 A 拦截回流扣量；并入「转仓 + 仓 B + 柜」 |
| 拦截回流 @ 仓 A | 再次拦截再回流 | 仍在「拦截回流 + 仓 A + 柜」 |

- 不做下单 FC × 派送方式 × 状态的多维合计矩阵  
- 不在中间仓保留已转走量的合计行
